## 待收尾事项

### P2-1：脚本预算回归断言与当前功能范围不匹配

位置：`tests/site.test.mjs:96`，性能/维护。

`npm test` 的唯一失败项将所有动态依赖也计入每页 50KiB 上限。首页总可加载脚本 gzip 为 230,819 字节，确实超过该上限；但静态导入的初始脚本为 48,588 字节，并非进入首页就加载全部三维代码。四个科研页面各约 9,028 字节，选模页约 9,018 字节，详情初始脚本约 11,984 字节。指标是独立模块 gzip 之和，不是实测网络传输或加载耗时。

影响：功能可用，但现有回归测试不会全绿，也无法准确区分首屏性能回退和主动打开三维展示的成本。

建议：保留初始脚本预算，另为明确按需加载的三维模块设置单独预算，并保留首屏未加载三维依赖的行为约束；不要简单删除测试或无条件放宽所有页面。建议工作：`$impeccable optimize`。

### P2-2：模型详情缺少禁用 JavaScript 时的高清图片入口

位置：`src/pages/models/[id].astro:18`、`src/components/ModelStageControls.astro`，无障碍/失败回退。

高清图区域默认 `hidden`，顶部“细节图”为脚本驱动按钮。源模板没有该详情页的 `noscript` 图片链接。正常浏览器的切换已经验证；禁用脚本时，访问者仅能看到加载后备图，无法通过此控件打开高清图片。此项是模板代码确认，没有用浏览器禁用脚本重新模拟。

影响：不影响正常启用 JavaScript 的当前主要流程，影响无脚本访问和增强代码未执行时的内容可达性。

建议：提供可直接打开高清图的无脚本入口，或让图片入口先作为原生链接，再由脚本增强为同屏切换；同时保持一屏模式。建议工作：`$impeccable harden`。

### P3-1：维护说明有历史描述

位置：`README.md` 的“静态发布配置”，以及 `PRODUCT.md` 的早期展柜段落，维护一致性。

README 仍写“无 GSAP、WebGL”，PRODUCT 的早期段落仍描述六扇区、分页与尚未部署；当前已使用 GSAP 和 Three.js，并采用七件作品单环和一屏详情。后续 surface 文档已有最新合同。

影响：当前线上访问正常，新维护者可能误判运行时、发布状态或布局规则。

建议：在维护收尾中同步当前功能与发布状态。建议工作：`$impeccable document`；如做界面收尾，以一次 `$impeccable polish` 结束，不重复整站审核。
